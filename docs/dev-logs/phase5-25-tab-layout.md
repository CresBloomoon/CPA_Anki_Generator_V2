# Phase5-25: タブ化＋設定保存挙動の変更＋C-2のブラウザ標準確認への変更

## 背景

Phase5-17〜5-20（生成進捗の表形式化＋セクション単位ダウンロード）に着手する
にあたり、画面構成を「メイン」「設定」「履歴」の3タブに統一する設計が
まーくんとの間で確定した。履歴タブ自体（Phase7-2）は今回まだ着手しないが、
タブの器は本Phaseで用意する。

あわせて、以下2点の追加決定が今回の議論の中で確定した：
- 設定タブでの保存後は、タブに留まったままトースト通知のみで成功を知らせる
  （タブを自動切り替えしない）
- C-2（リセットボタン押下時、完了済み未ダウンロードのカードがある場合の
  確認ダイアログ）を、`Modal.tsx`を使ったカスタム実装からブラウザ標準の
  `window.confirm()`に変更する。この結果、`Modal.tsx`の利用箇所がゼロに
  なるため、ファイル自体を削除する

## 何を実装したか

- `frontend/src/App.tsx`（修正）
  - `isSettingsModalOpen`を`activeTab: 'main' | 'settings' | 'history'`
    （初期値`'main'`）に置き換え、3つのタブボタンを新設
  - 歯車アイコン単体のボタンを廃止し、設定はタブの1つとして扱う形に変更
  - `SettingsPanel`を`Modal`から取り出し、`activeTab === 'settings'`の
    条件でそのままタブ内容として描画するよう変更
  - `handleSettingsSaved()`から`setIsSettingsModalOpen(false)`を削除し、
    トースト通知のみ残した
  - `isResetConfirmOpen`のstateと、対応する`Modal`のJSXブロックを削除。
    `handleResetClick()`内で、`doneCount > 0 && !hasDownloaded`の場合に
    `window.confirm()`を呼び出す形に変更。文言は既存のモーダルの本文
    （完了件数・失われる旨の説明）を1つの確認文に統合した
  - 「メイン」相当の既存コンテンツ（アップロード〜ダウンロードボタン）を
    `activeTab === 'main'`の条件で囲み、「履歴」タブには準備中の
    プレースホルダーを配置
- `frontend/src/components/Modal.tsx`（削除）
  - 上記の変更により利用箇所がゼロになったため、ファイルごと削除
- `frontend/src/components/icons.tsx`（修正）
  - `Modal.tsx`削除に伴い唯一の参照元を失った`CloseIcon`を削除
  - あわせて、歯車アイコンボタンの廃止により同様に未使用となっていた
    `GearIcon`も削除（実装中に発見、Todo作成時点では`CloseIcon`のみを
    想定していたが、同じ理由で対応した）

## 実装中に発見したバグ・問題点

`icons.tsx`の`GearIcon`が、Todo作成時点で想定していなかった形で未使用に
なっていることを実装中に発見した。歯車アイコン単体のボタンをタブ化に伴い
廃止したことの直接的な副作用であり、`CloseIcon`と同じ「死んだエクスポートを
残さない」という理由で、範囲を広げて併せて削除した。

## 大きな判断とその理由

- **設定保存後はタブに留まる**：モーダルには「閉じる」という概念があったが、
  タブにはそれに相当する操作が無い。トースト通知（既存のPhase5-12の仕組み）
  だけで保存成功を十分に表現できるため、自動切り替えは行わないこととした。
- **C-2をカスタムモーダルからブラウザ標準の`window.confirm()`に変更した**：
  赤色ボタン等の視覚的な警告表現は不要と判断された。`window.confirm()`は
  1つの文字列しか渡せないため、既存モーダルの本文（完了件数・ダウンロード
  未実施・カードが失われる旨）を1文に統合し、末尾に「よろしいですか？」を
  付けて確認の体裁を整えた。
- **`Modal.tsx`をリファクタリングで温存せず削除した**：今回の変更で利用箇所が
  実際にゼロになることを`grep`で確認した上で削除している。将来的に別の
  モーダルが必要になった場合は、その時点で改めて実装する方針とし、
  「いつか使うかもしれない」という理由で未使用のコンポーネントを残すことは
  しなかった。

## ADR

今回はADRを書くレベルの設計判断はなし。
