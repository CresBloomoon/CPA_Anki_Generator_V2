# Phase5-27: タブのファビコンによる状態表示

## 背景

Claudeのチャット画面と同様の挙動（生成中・完了未ダウンロードをタブ切り替え
無しで把握できるようにする）を、タブのfaviconを使って実現する。当初は小さい
ドット表示、続いて回転スピナー案、静止アイコン（砂時計・チェックマーク）
でのfavicon全体差し替え案を検討したが、実機確認で「favicon全体を差し替える
と大元のロゴが完全に見えなくなる」ことが判明し、**大元のロゴ画像は維持した
まま、右下に小さい色付きドットを重ね描きする方式**に変更した（生成中＝青い
ドット、完了かつ未確認＝緑のドット）。

さらに実機確認を経て、「両ドットともタブが非アクティブな間だけ表示する」
という当初の条件も見直した。最終的には**タブのアクティブ／非アクティブを
一切条件にせず**、「青：生成中は常時表示」「緑：生成が停止してから
ダウンロードするまでの間、常時表示」というシンプルな仕様に確定した。

## 何を実装したか

- `frontend/src/utils/favicon.ts`（新規）
  - 実行時に既存の`<link rel="icon">`要素とその元の`href`を1回だけ取得・
    キャッシュする（将来favicon画像自体が差し替わっても、この読み取り
    ロジック自体は無修正で動く設計）
  - ベース画像（元のfavicon）を`Image`オブジェクトとして読み込み、
    モジュール内でキャッシュする`loadBaseImage()`を追加
  - `setFaviconIcon(kind: 'generating' | 'completed' | null): Promise<void>`
    を実装。ベース画像読み込みが非同期のため`async`関数とした。
    `<canvas>`にベース画像を描画した上で、右下に小さい円
    （`generating`＝青`#2563eb`、`completed`＝緑`#16a34a`、白の縁取り付き）
    を重ね描きし、`toDataURL()`の結果を`<link>`の`href`に設定する。
    `null`の場合は元の`href`に戻す
- `frontend/src/App.tsx`（修正）
  - `hasUndownloadedCompletion`（`!isCurrentlyGenerating && doneCount > 0
    && !hasDownloaded`）を、新規stateを一切増やさずに導出。C-2の確認
    ダイアログが使っている`doneCount`／`hasDownloaded`をそのまま再利用
    している
  - `faviconIconKind`（`'generating' | 'completed' | null`）を、
    `isCurrentlyGenerating`と`hasUndownloadedCompletion`から算出
  - `faviconIconKind`を監視する`useEffect`で`void setFaviconIcon()`を
    呼び出す（`async`化に伴い戻り値のPromiseを明示的に無視する）
  - タブのアクティブ／非アクティブを条件から外したことに伴い、
    `isTabVisible`のstateと`visibilitychange`購読の`useEffect`、
    `hasUnseenCompletion`のstateと`is_complete`変化監視の`useEffect`、
    `performReset()`内の`setHasUnseenCompletion(false)`は、いずれも
    不要になったため削除した

## 実装中に発見したバグ・問題点

なし。

## 大きな判断とその理由

- **回転スピナー案を断念し、静止表現にした**：以下3点を理由に、
  まーくんの判断でアニメーション無しに確定した：
  - タブ非アクティブ時のブラウザによるタイマー間引き（Chromeは非表示
    タブの`setInterval`を早い段階で最短1秒に切り上げ、5分以上の長時間
    非表示ではさらに間引く）により、なめらかに回らずコマ飛びして見える
    可能性があったこと
  - 実装・状態遷移の複雑さやテストのしにくさが増す割に、「あったら
    いいな」レベルの機能としては割に合わないと判断したこと
  - 静止表現でも状態変化を伝える目的は十分果たせると判断したこと
  - なお調査の過程で、`requestAnimationFrame`は非表示タブでは呼び出し
    自体が停止するため今回の用途に使えず、`setInterval`を使う必要が
    あるという技術的な知見も得たが、上記の判断によりそもそも
    アニメーション自体を実装しないこととなったため、この知見は記録
    としてのみ残す
- **当初は静止アイコン（砂時計・チェックマーク）でfavicon全体を差し替える
  方式を採用したが、実機確認の結果ベース画像への小さいドットの重ね描き
  方式に変更した**：全体差し替え方式は「16〜32px程度の小さいfaviconサイズ
  では、ベースのロゴと記号を重ねて描くと視認性が悪くなる」という懸念から
  意図的に選んだものだったが、実際に動かしてみると**大元のロゴアイコンが
  完全に見えなくなる**という、意図しない見た目になることが実機確認で
  判明した。まーくんと相談の上、「単純な小さいドットであれば視認性への
  影響は限定的」という判断で、ベース画像は維持したまま右下に小さい円を
  重ね描きする方式に作り直した。アイコン形状（砂時計・チェックマーク）
  は、小さい円との組み合わせでは表現が難しいため廃止し、色分け（青／緑）
  のみで状態を区別する形にした
- **タブのアクティブ／非アクティブを条件から外し、専用stateを廃止して
  既存の値から導出する形に作り直した**：実機確認の結果、「タブが
  非アクティブな間だけ表示する」という当初の仕様よりも、「青は生成中
  常時、緑は未ダウンロードの間常時」というシンプルな仕様の方が実際の
  使い方に合うと判断した（まーくんとの合意事項）。この見直しにより、
  緑ドットの表示条件はC-2の確認ダイアログが既に使っている
  `doneCount > 0 && !hasDownloaded`という条件とほぼ同じものになり、
  `hasUnseenCompletion`・`isTabVisible`という専用stateと、それらを
  更新する2つの`useEffect`が丸ごと不要になった。新規state・
  `useEffect`を増やさず、既存の導出値の組み合わせだけで表現できた点は、
  結果的に機能追加というよりは簡素化になった
- **複数タブの考慮は行わなかった**：favicon・`document.visibilityState`
  はブラウザタブごとに完全に独立しており、各タブが自分自身の状態だけを
  見て自分自身のfaviconを描画すればよいため、タブ間の同期機構
  （`BroadcastChannel`等）は不要と判断した
