# Phase5-9: PDFドラッグ&ドロップアップロードエリア

## 何を実装したか

- `frontend/src/components/UploadPanel.tsx`（修正）
  - `<input type="file">`を非表示化（`className="hidden"`）し、`ref`経由で参照。角丸点線枠の`<div>`をクリックすると`fileInputRef.current?.click()`でダイアログを開く。ドラッグ&ドロップも同じエリアで受け付ける（クリック/ドロップの入口を一体化）。
  - `applySelectedFiles(files: File[])`：クリック選択・ドロップの両方から呼ばれる共通処理。PDF以外（`file.type !== 'application/pdf'`）を除外し、除外があれば一時的な警告メッセージを表示。PDFのみを既存の`selectedFiles`に加算（重複は除外——詳細は次項）。
  - チラつき対策：`onDragEnter`／`onDragOver`／`onDragLeave`／`onDrop`をラッパー`<div>`1つだけに付与し、内部の子要素（テキスト・`<input>`）すべてに`pointer-events-none`を指定。子要素がマウス/ドラッグイベントを一切拾わなくなるため、子要素の出入りによる`dragenter`/`dragleave`の誤発火（既知のチラつき問題）がそもそも発生しない。`onDragOver`内で`event.preventDefault()`を呼び、ブラウザの既定動作（ファイルを別タブで開く）を防いでいる。
  - 選択済みファイル一覧の各項目に削除ボタン（`TrashIcon`＋`iconButtonClasses`、Phase5-3/Phase5-8で確立済みのパターンを踏襲）を追加し、1件ずつ取り消せるようにした。
  - `handleFileChange`で`event.target.value = ''`をリセットし、同じファイルをもう一度選択してもブラウザの`onChange`が正しく発火するようにした（`<input>`のvalueが変化していないとブラウザが`change`イベントを発火しないため）。

## 実装中に発見したバグ・問題点

なし。

## 大きな判断とその理由

- **クリック選択も含めて全体を「加算」方式に統一した**：クリックとドロップの入口を1つのエリアに一体化する以上、操作方法によって「置き換え」と「加算」で挙動が異なると、同じ見た目のUIで結果が変わってしまい混乱を招く。まーくんとの合意により、両方とも加算に揃えた。
- **重複判定はファイル名＋サイズで行うことにした**：ファイル内容のハッシュ（例：`crypto.subtle.digest`）まで厳密に比較する案も検討したが、非同期でのファイル読み込みが必要になり実装コストが跳ね上がる。今回のユースケース（同じPDFをうっかり二重に選択してしまうのを防ぐ程度のガード）に対しては過剰と判断し、`file.name`と`file.size`という同期的に取得できる情報だけで十分と判断した。万が一「同名・同サイズだが中身が違う別ファイル」が誤って重複除外される可能性はゼロではないが、極めて稀なケースであり実用上問題ないと判断した。
- **加算方式にする以上、個別削除ボタンを追加した**：全消しの「リセット」ボタンしか無い状態で加算方式にすると、1件だけ間違えて追加してしまった場合に取り消す手段が無くなる。まーくんとの合意により、選択済み一覧の各項目に削除ボタンを追加した。
- **PDF判定はクリック選択でも`applySelectedFiles`を通して行うようにした**：`accept="application/pdf"`はネイティブのファイル選択ダイアログにのみ効き、ドラッグ&ドロップには適用されない。OS/ブラウザによってはダイアログ側の「すべてのファイル」表示でこのフィルタを迂回できてしまう可能性もあるため、入口（クリック/ドロップ）によらず一貫した挙動にするため、共通処理側でも明示的にPDF判定を行うことにした。
